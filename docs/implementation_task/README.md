# Implementation Tasks

Scoped, execution-ready implementation tasks for `etfhextractor`. Each task is a
self-contained plan: objective, current state, target architecture, ordered work
items, a verified symbol reference, a testing/validation plan, and open questions.

| Task | Status | Summary |
|---|---|---|
| [0001 — Migrate category sync to ms-markets](0001-migrate-to-ms-markets.md) | Implemented | Route asset resolution and `HOLDINGS__<ETF>` category sync through `ms-markets` (`msm`) instead of `mainsequence.client` (which no longer exposes `Asset`/`AssetCategory` in SDK 4.3.16, so the current path is already broken). Ticker→asset resolver: the msm asset-snapshot layer (§10.1). |
| [0002 — ETF-tracking portfolio via custom signal](0002-ms-markets-portfolio-weights.md) | Implemented + live-validated (findings folded into §5.5–§5.6, ADRs 0005/0006) | Follow-up to 0001: `ETFHoldingsSignal` (custom `msm_portfolios` `SignalWeights`) updates weights from the extraction — guarded to insert at most daily and only on change — and `PortfoliosDataNode` builds a portfolio that tracks the ETF (weights do not live on the category — see [ADR 0003](../adr/0003-holdings-weights-live-in-ms-markets-portfolios.md)). |
| [0005 — SDK 8 and ms-markets 1 migration](0005-sdk8-ms-markets1-migration.md) | Implemented; backend verified | Preserves extraction, category/FIGI, signal, portfolio-publish, reusable portfolio assembly, and demo migrations while moving updater and registered-table references to the SDK 8 contracts. |
| [0006 — SDK 9, MetaTables client and ms-markets 2 migration](0006-sdk9-metatables-ms-markets2-migration.md) | Implemented; verified offline (lock regeneration and backend check pending ms-markets 2.0.0 on PyPI) | Moves MetaTables imports and migration commands to the `metatables` client (`mainsequence-metatable`), drops the SDK 8.1-removed run controls and the ms-markets 1.0.7-removed strategy calendar key, and keeps the migration provider, its revisions, and every public name downstream projects use. |
| [0007 — SDK 9.0.22, MetaTables 0.1.34 and deployment-Job migrations](0007-deployment-job-migrations.md) | Implemented in 0.4.3 (not published) and released in 0.4.4; provider proven on isolated local SQLite against the real ms-markets schema on MetaTables 0.1.18, 0.1.20 and 0.1.34 (2026-10-11, ms-markets 2.2.10); local end-to-end run recorded with three ms-markets SQLite defects | Requires `mainsequence` 9.0.22, `mainsequence-metatable` 0.1.34 and exactly ms-markets 2.2.10. Hosted runtimes are migrated only by the migration Job of the application that deploys `DemoBarsTS` (this library has no deployment), which needs a MetaTables API on 0.1.32 or later and the Team that owns the `etfhextractor` namespace; local development uses `metatables --local`; the schema-prep example never migrates hosted runtimes. |
| [0003 — FIGI registration of missing components](0003-figi-asset-registration.md) | Implemented + live-validated (503/503 IVV components registered) | Register unresolved component tickers through OpenFIGI under [ADR 0004](../adr/0004-figi-only-asset-registration.md): no FIGI → no registration, and only unique ticker→FIGI mappings register (ambiguity stays a blocker). Opt-in via `--register-missing`. |

No agent runtime — capabilities are served through the existing CLI. |
